# 每周知识复习：信息架构与完整用户路径

版本：v1  
目标：先解决“难理解、步骤多、入口分散”，再进入视觉设计与前端改造。

## 1. 产品心智模型

用户不需要理解令牌、API、数据管线或周报归档规则。产品只向用户呈现四件事：

1. **保存**：把值得记住的 AI 对话收进来。
2. **筛选**：自动排除让 AI 干活、闲聊和不值得复习的内容。
3. **回顾**：把本周知识整理成自然的复习文章。
4. **练习**：通过主动回忆 Quiz 检查自己是否真的记住。

产品的核心循环：

```text
日常保存对话 → 本周内容累积 → 生成本周回顾 → 做 Quiz → 下周继续
```

所有页面、导航和文案都应服务于这条循环。

## 2. 当前结构的问题

当前页面从实现模块出发，而不是从用户任务出发：

- 首页同时承担免登录试用、产品说明、登录入口、移动保存入口和插件周报入口。
- `/my`、`/save`、`/history`、`/settings/token` 名称和层级缺少统一关系。
- “插件采集”“手机网页保存”“接入令牌”“生成本周复习”被展示成多个平级概念。
- 登录后的第一落点是令牌管理，而不是用户真正想看的本周内容。
- 用户必须先理解系统怎么工作，才能判断下一步应该点哪里。

新版原则：

- **一个首页、一个应用壳、一个主循环。**
- **技术配置后置，用户任务前置。**
- **每个页面只有一个主动作。**
- **先让用户看到价值，再要求注册和安装。**
- **空状态负责教下一步，不依赖单独的长篇说明。**

## 3. 新版信息架构

### 3.1 未登录区域

| 路径 | 页面 | 主要任务 |
| --- | --- | --- |
| `/` | 产品首页 + 即时试用 | 在 30 秒内理解价值并生成第一份回顾 |
| `/login` | 登录 | 通过邮箱继续保存进度 |
| `/privacy` | 隐私政策 | 解释数据处理与保存边界 |
| `/terms` | 使用条款 | 产品使用规则 |

未登录首页不再出现“插件令牌”“手机网页保存”等产品内部概念。

### 3.2 登录后应用区域

统一放入 `/app`，使用固定应用导航。

| 路径 | 页面 | 主要任务 |
| --- | --- | --- |
| `/app` | 本周 | 查看本周进度、生成或继续本周回顾 |
| `/app/capture` | 保存对话 | 手动粘贴保存；同时作为移动端分享落点 |
| `/app/history` | 历史 | 查看过去每周的回顾与 Quiz |
| `/app/settings` | 设置 | 管理采集方式、时区、数据和账号 |
| `/app/setup` | 首次设置 | 选择最适合自己的采集方式 |
| `/app/setup/extension` | 连接扩展 | 一键连接，手动令牌只作为故障备用 |

### 3.3 导航

桌面顶部导航：

```text
[品牌]  本周  历史                      [保存对话] [头像/设置]
```

移动底部导航：

```text
本周       保存       历史       我的
```

规则：

- “保存对话”始终是全局可见的强调动作。
- “设置”不进入主循环，不与“本周”争夺视觉权重。
- “扩展”“时区”“令牌”“导出”“删除账号”全部归入设置。
- 正常用户永远不需要看到“令牌”二字。

## 4. 页面层级

### 4.1 首页 `/`

目标：让用户先看到结果，而不是先学习产品。

首屏结构：

1. 一句话价值：
   - 标题：`别让你问过 AI 的好问题，就这样消失。`
   - 副标题：`保存知识型对话，每周得到一份自然回顾和主动回忆小测验。`
2. 两个动作：
   - 主按钮：`试试示例`
   - 次按钮：`粘贴我的对话`
3. 可直接使用的输入区。
4. 三个短标签：
   - `自动排除让 AI 干活`
   - `对话试用不保存`
   - `生成回顾与 Quiz`

结果生成后：

- 原地展示回顾与 Quiz。
- 结果顶部不显示注册墙。
- 结果底部只显示一个转化动作：
  - `以后自动收集这些知识 → 免费登录`

首页底部才解释“三步工作方式”和隐私。

### 4.2 本周 `/app`

目标：用户打开产品后，一眼知道“本周存了多少、现在该做什么”。

页面分为四层：

1. **本周状态**
   - 日期范围。
   - 已保存内容数。
   - 最近一次保存时间。
   - 当前状态：等待内容 / 可以生成 / 已生成 / 有新内容可更新。
2. **唯一主动作**
   - 无内容：`保存第一段对话`
   - 有内容但未生成：`生成本周回顾`
   - 已生成且有新内容：`更新本周回顾`
   - 已生成且无变化：`继续做 Quiz`
3. **回顾正文**
   - 文章式阅读，不放入普通卡片瀑布流。
4. **Quiz**
   - 单题卡片。
   - 显示进度，例如 `2 / 4`。
   - 先作答，再揭示答案，再自评。

不在本页展示：

- 登录邮箱。
- 令牌管理链接。
- 归档和原始内容清理规则。
- 数据库或模型处理方式。

这些内容放入设置或帮助说明。

### 4.3 保存对话 `/app/capture`

目标：任何设备上都能在一个动作内完成保存。

页面结构：

1. 标题：`保存这段对话`
2. 输入框。
3. 主按钮：`保存`
4. 成功状态：
   - `已保存 2 条知识内容`
   - `另有 1 条重复内容已跳过`
   - 下一动作：`返回本周`
5. 次要说明：
   - `我们会在生成周报时自动排除让 AI 干活和闲聊的部分。`

移动端支持：

- Web Share Target 或 iOS 快捷指令最终都进入同一页面。
- 分享进来时自动填充内容。
- 已登录时直接保存；未登录时先登录，再恢复待保存内容。

### 4.4 历史 `/app/history`

目标：像查看周刊目录一样回看，不使用大量折叠面板。

结构：

- 顶部按年份筛选。
- 每周一张轻量目录卡：
  - 周日期。
  - 本周主题摘要。
  - 内容数量。
  - Quiz 完成情况。
- 点击进入独立详情页 `/app/history/[week]`。

详情页保持与“本周回顾”一致的阅读和 Quiz 体验。

### 4.5 设置 `/app/settings`

按用户语言分为四组：

1. **采集方式**
   - 浏览器扩展：已连接 / 未连接。
   - 手机保存：添加到主屏幕 / 创建分享快捷方式。
2. **每周回顾**
   - 时区。
   - 一周开始日。
   - 未来可加入通知时间。
3. **数据**
   - 导出数据。
   - 隐私说明。
4. **账号**
   - 邮箱。
   - 退出登录。
   - 删除账号。

“手动令牌”放在：

```text
采集方式 → 浏览器扩展 → 遇到连接问题？ → 手动配置
```

默认折叠，不进入普通使用路径。

## 5. 完整用户路径

### 5.1 首次体验：先看到价值

```text
进入首页
→ 点击“试试示例”
→ 自动填入一段混合知识问题和工作请求的对话
→ 点击“生成回顾”
→ 看到工作请求被过滤、自然周报和 Quiz
→ 完成一道 Quiz
→ 页面提示“以后自动收集这些知识”
→ 用户选择是否登录
```

成功标准：

- 不登录也能完成完整价值体验。
- 从进入首页到看到结果不超过 60 秒。
- 用户无需知道插件或令牌是什么。

### 5.2 登录与首次设置

```text
点击“免费登录”
→ 输入邮箱
→ 邮件中点击登录
→ 回到 `/app/setup`
→ 页面询问“你通常在哪里和 AI 对话？”
→ 桌面浏览器 / 手机 / 两者都用
→ 根据选择展示一个推荐步骤
```

桌面浏览器：

```text
安装扩展
→ 返回网站
→ 点击“一键连接”
→ 显示“已连接”
→ 引导用户去任一 AI 页面保存第一段对话
```

手机：

```text
显示“添加保存入口”
→ iOS：添加快捷指令或添加到主屏幕
→ Android：安装 PWA / 分享到本产品
→ 完成一次测试保存
```

两者都用：

- 先完成桌面扩展。
- 手机入口作为第二步，可跳过。

首次设置只在用户完成一项可用采集方式后结束。

### 5.3 浏览器日常保存

```text
用户在 Claude / ChatGPT / DeepSeek 完成一段对话
→ 打开扩展
→ 主按钮显示“保存这段对话”
→ 点击
→ 显示“已保存 3 条，1 条重复已跳过”
→ 可直接关闭扩展
```

扩展默认界面只保留：

- 连接状态。
- `保存这段对话` 主按钮。
- 最近一次保存结果。
- `打开本周回顾` 链接。

手动服务地址、令牌、断开连接和重试队列放进设置页。

### 5.4 手机日常保存

首选路径：

```text
在 AI App 或浏览器中选择文字 / 复制对话
→ 系统分享
→ 选择“保存到每周回顾”
→ 显示保存成功
→ 返回原应用
```

兜底路径：

```text
打开 `/app/capture`
→ 粘贴
→ 保存
```

### 5.5 每周回顾

当前阶段继续由用户触发，避免无意识产生模型成本：

```text
用户进入 `/app`
→ 看到“本周已保存 12 条，可以生成回顾”
→ 点击“生成本周回顾”
→ 显示生成进度
→ 阅读回顾
→ 完成 Quiz
```

后续商业版本可增加：

- 周末自动生成。
- 邮件或系统通知。
- 用户选择生成时间。

### 5.6 内容为空

```text
进入 `/app`
→ 显示“这周还没有保存内容”
→ 主按钮“保存第一段对话”
→ 次按钮“连接浏览器扩展”
```

不要只告诉用户“还没有周报”，必须给出一个能立即完成的下一步。

### 5.7 生成后有新内容

```text
已有本周回顾
→ 用户又保存了新对话
→ 本周页显示“新增 3 条内容”
→ 主按钮变为“更新本周回顾”
```

系统应明确“更新会把新内容加入本周回顾”，避免用户把“刷新”理解成重新加载页面。

## 6. 页面状态模型

本周页只使用以下四种状态：

| 状态 | 条件 | 主文案 | 主动作 |
| --- | --- | --- | --- |
| `empty` | 本周 0 条 | 这周还没有保存内容 | 保存第一段对话 |
| `ready` | 有内容、无回顾 | 已保存 N 条，可以生成回顾 | 生成本周回顾 |
| `current` | 已生成、无新增 | 本周回顾已准备好 | 继续做 Quiz |
| `stale` | 已生成、有新增 | 回顾生成后又新增 N 条 | 更新本周回顾 |

生成过程：

```text
正在筛选值得复习的内容
→ 正在整理本周主题
→ 正在生成回顾与 Quiz
```

不显示模型名称、API 调用或技术错误。

## 7. 文案规范

### 7.1 使用用户语言

| 不再使用 | 改为 |
| --- | --- |
| 存入复习 | 保存这段对话 |
| 我的本周复习 | 本周回顾 |
| 刷新本周 | 更新本周回顾 |
| 插件采集的数据 | 保存过的对话 |
| 接入令牌 | 手动连接码，仅在高级设置出现 |
| 生成失败，502 | 暂时没能生成，请稍后再试 |
| items / 条目 | 内容 / 对话 |

### 7.2 每页一个主动作

- 首页：`生成回顾`
- 本周：根据状态变化的一个主动作
- 保存页：`保存`
- 首次设置：`继续`
- 扩展连接页：`连接扩展`
- 历史详情：`开始 Quiz` 或 `继续 Quiz`

### 7.3 说明文字原则

- 先说明用户能得到什么，再说明系统怎么做。
- 一段只表达一个信息。
- 普通页面不出现数据库、API、令牌、RPC、模型名称。
- 隐私说明清楚但不抢占首屏。

## 8. 登录与重定向规则

- 未登录访问 `/app/**`：跳转 `/login?next=<原路径>`。
- 登录成功：
  - 未完成首次设置：进入 `/app/setup`。
  - 已完成首次设置：回到 `next` 或 `/app`。
- 已登录访问 `/`：
  - 仍允许看公开首页。
  - 顶部主按钮改为 `进入本周回顾`。
- 从移动分享进入但未登录：
  - 临时保留待保存文本。
  - 登录后恢复到 `/app/capture`。
- 从扩展连接进入但未登录：
  - 登录后回到 `/app/setup/extension`。

建议在 `user_profiles` 增加：

```text
onboarding_completed_at
preferred_capture_method
```

不要用“是否生成过令牌”推测是否完成首次设置。

## 9. 旧路由迁移

先保留兼容跳转，避免旧链接和扩展失效。

| 旧路径 | 新路径 |
| --- | --- |
| `/my` | `/app` |
| `/save` | `/app/capture` |
| `/history` | `/app/history` |
| `/settings/token` | `/app/settings` |
| `/connect-extension` | `/app/setup/extension` |

API 路径保持不变，降低改造风险。

扩展中的生产域名保持不变，仅更新打开的网页路径。

## 10. 产品成功指标

重点观察漏斗，而不是只统计注册数：

1. 首页访问 → 开始第一次生成。
2. 开始生成 → 成功看到回顾。
3. 看到回顾 → 揭示第一道 Quiz。
4. 完成试用 → 登录。
5. 登录 → 完成一种采集方式。
6. 完成采集设置 → 成功保存第一段对话。
7. 第一段保存 → 生成第一份登录态周报。
8. 次周仍然保存内容。

建议的首轮目标：

- 首页体验启动率 ≥ 35%。
- 生成成功用户中的 Quiz 揭示率 ≥ 50%。
- 登录用户中的采集设置完成率 ≥ 70%。
- 设置完成用户中的首次保存成功率 ≥ 80%。

## 11. 落地顺序

### Phase 1：结构和文案

- 新增 `/app` 应用壳和统一导航。
- 将旧路由迁移到新结构。
- 重写首页、登录后首页和所有主按钮文案。
- 隐藏正常流程中的令牌管理。

### Phase 2：首次使用

- 增加首页“一键示例”。
- 增加登录后的 `/app/setup`。
- 增加采集方式选择和完成状态。
- 登录回调按首次设置状态分流。

### Phase 3：核心循环

- 本周页增加四态模型。
- 展示内容数、最近保存时间和新增内容数。
- 生成过程改为分阶段反馈。
- Quiz 改为单题模式和进度模式。

### Phase 4：采集体验

- 精简扩展 Popup。
- 移动端接入 Web Share Target / PWA。
- 保存成功提示统一。

### Phase 5：视觉系统

- 建立颜色、字体、间距、阴影、卡片和按钮规范。
- 重做首页 Hero、本周阅读版式与 Quiz 动效。
- 完成移动端和桌面端视觉验收。

## 12. 本轮设计结论

本轮不改变核心能力和后端管线，只改变用户看到的结构：

- 公开试用仍然无登录、无持久化。
- 登录用户仍然通过现有 API 保存和生成。
- 模型 Prompt 不变。
- 浏览器采集仍然由用户主动触发。
- 正常用户路径不再暴露令牌。
- 视觉设计应在信息架构落地后开始，避免只给旧结构“换皮”。
